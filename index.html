            How hostile is the internet?

            Any machine that puts SSH on the public internet is found and attacked by automated tools, usually within minutes. Nearly all of it is untargeted: credential stuffing against common accounts and passwords, port and service scanning, and scripted fingerprinting. The busiest sources are frequently rented servers, proxies, or compromised machines — not the people operating the tools — so a source address rarely says who is behind an attempt.

            About this project

            This is a small research project: a single Cowrie SSH honeypot exposed on the public internet and left to record whatever automation finds it. Everything below is derived from that one sensor, which is why it says more about automated background traffic than about "the internet" as a whole.

            The sensor

            Instead of running real services, the sensor logs every session and emulates a shell. It presents itself as an ordinary small Linux web server — filesystem, processes, and command output — so that automated tools behave as they would against a real host. It is isolated from any production system. It also accepts a broad range of credentials on purpose, so sessions continue past login and the commands that follow can be observed; a login success here is a design choice, not a compromised machine.

            The pipeline

            1. The sensor writes one JSON log line per event on the private host.
            2. An hourly job folds the most recent 90 days into a small local index; a daily job derives the 24-hour, 7-day, 30-day, and 90-day windows shown here.
            3. Completed logs are archived to a private Cloudflare R2 bucket, and a scheduled GitHub Action folds that archive into the all-time aggregate.
            4. Only sanitized aggregates are committed here and rendered as a static page — no server, no analytics, no third-party runtime dependency.

            What the bots do

            After connecting, most sessions run a short fingerprinting burst — uname, hostname, whoami, lscpu, netstat, df and similar — then try to fetch a payload or persist. The command list above is normalized to executable names, and a file hash that keeps reappearing is usually a reusable installer or binary pulled from a URL. Attempted usernames are overwhelmingly generic (root, admin, ubuntu).

            What is published

            Counts, country codes, top public source IPs, normalized command names, attempted usernames, and captured-file SHA-256 hashes. Passwords, login messages, complete command lines, URLs, session identifiers, and captured file contents or samples never leave the private host. The archive holds completed logs, so the all-time view lags the live windows by up to one rotation.

            Limitations and ethics

            Treat these as observations, not attribution: source addresses may be VPNs, relays, scanners, or compromised machines, and country values are approximate. Counts include repeated automation from a single address and are affected by the sensor's uptime. Operate honeypots only on infrastructure you control and only where you are permitted to.
